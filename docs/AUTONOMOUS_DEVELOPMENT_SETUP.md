# DiveEnd 长期自治开发前置清单

更新时间：2026-07-30

## 目的

这份文档定义 DiveEnd 长期开发中的责任边界，使 LLM agent 能够持续完成“理解现状、选择任务、实现、测试、桌面验收、更新文档、提交代码、报告结果”的闭环，同时把必须由项目所有者完成的身份认证、付费授权、法律确认和高风险操作保留为人工闸门。

本文按工作类型分类，不按开发阶段分类。项目现状和代码映射仍以 `README.md`、`AGENTS.md` 和 `docs/PROJECT_MAP.md` 为准。

## 已确认的运行决策

项目所有者已于 2026-07-30 确认：

- 第一目标用户是项目所有者本人，产品按个人研究者的本地优先桌面工作台设计。
- 功能设计 `F1-F8` 全部接受。
- 界面设计 `U1-U8` 全部接受。
- 允许 agent 自动创建分支、commit、push、创建 PR、启动本地服务并使用本地凭证执行受控真实 E2E。
- API 授权上限为每天 1 亿 token。强弱模型共享持久化的每日计数器，请求前预留额度、请求后按 provider usage 结算；provider 不返回 usage 时采用保守估算。达到上限后后端会在发送请求前停止。
- 不考虑向其他 Mac 用户分发，暂不申请 Apple Developer Program，也不开展签名和 notarization。
- 合并正式分支、公开发布、Git 历史重写、超预算付费和真实云数据破坏性操作仍保留人工闸门。

## 一、LLM Agent 可以自动化完成

### 项目治理与任务选择

- 阅读当前权威文档和实际代码，校正文档与实现之间的偏差。
- 维护 `README.md`、`AGENTS.md`、`docs/PROJECT_MAP.md`、测试说明和变更记录。
- 从已确认的产品目标、缺陷、测试结果和技术债中选择下一项高价值工作。
- 将历史规格视为背景资料，不让过期的 Marker、GORM 等描述重新进入当前实现。
- 检查工作区、分支、远端和忽略规则，避免把本地数据、构建产物或密钥提交到 Git。

### 产品与代码开发

- 在现有 React/TypeScript、Go/Wails、SQLite、Python/FastAPI 架构内实现前后端功能。
- 重构检索、AI 辅助阅读、总结分析、文库、筛选、同步和设置功能。
- 补齐加载、空状态、失败、重试、取消、恢复、离线和窄窗口等交互状态。
- 对第三方服务增加超时、限流、重试、缓存、降级、错误脱敏和可诊断信息。
- 维护数据库迁移、前后端类型、Wails bindings、配置模板和兼容逻辑。
- 在设计已对齐的范围内持续改善界面，不需要为每个像素调整重新等待确认。

### 自动测试与真实交互验证

- 运行 Go、前端和 PDF service 的单元测试、集成测试、构建、静态检查和密钥扫描。
- 为修复的缺陷和新增行为补回归测试。
- 启动 `wails dev` 或打包后的桌面应用，通过 computer-use 点击真实界面。
- 观察按钮、路由、事件、数据库、文件系统、网络请求和后端日志之间的数据流。
- 使用可重复的本地 fixture 验证检索、PDF 解析、AI 依据、笔记、导入和同步预览。
- 在本地凭证可用时执行受控的 Semantic Scholar、LLM 和百度网盘真实请求。
- 对外部网络失败与代码缺陷分别归因，不把供应商故障误判为产品成功。

日常 CI 默认不依赖付费模型或个人云账号。真实服务 E2E 应是显式触发、有限预算、避免破坏数据的验收任务。

### 版本控制与交付

- 在允许的分支范围内创建 `codex/*` 分支、提交、推送并维护 Pull Request。
- 提交前运行 `bash scripts/secret_scan.sh` 和与改动相称的测试。
- 生成变更说明、测试证据、已知限制和下一步建议。
- 建立 GitHub Actions，自动执行测试、构建、依赖审计和 secret scan。
- 生成内部测试包、校验文件、版本说明和 ZIP 归档。
- 发现失败后继续定位、修复、复测，而不是停在“命令失败”的状态。

### 持续自治工作循环

```text
读取权威文档和 git 状态
  -> 核对实现与实际风险
  -> 选择已授权范围内最高价值任务
  -> 创建或使用工作分支
  -> 实现前端、后端和必要迁移
  -> 自动测试与桌面交互验收
  -> 更新项目状态和代码映射
  -> secret scan
  -> commit / push / PR
  -> 报告结果、证据、风险和下一任务
```

### 默认需要保留的人工闸门

以下操作即使技术上可以自动执行，也不得默认自动进行：

- 合并到受保护分支或发布正式版本。
- 产生超出约定额度的付费 API 消耗。
- 删除、覆盖或大批量修改真实云端数据。
- 对外公开仓库、安装包、网站或用户数据。
- 接受平台协议、完成实名验证、付款或法律声明。
- 轮换、吊销或删除仍在使用的凭证。
- 重写 Git 历史、强制推送或更改协作者可见的提交历史。
- 开启遥测、上传论文内容或收集任何用户数据。

## 二、短期需要与你对齐的设计

下面记录会显著改变开发方向的设计决定。项目所有者已于 2026-07-30 全部接受，后续 agent 应直接按这些约束实施，除非项目所有者明确修改。

### 功能设计

| 编号 | 需要确认的问题 | 建议默认值 |
| --- | --- | --- |
| F1 | 第一目标用户是谁 | 先做个人研究者的本地优先桌面工具，不先承担团队协作和公共 SaaS 的复杂度。 |
| F2 | 核心任务的优先顺序 | 固定为“检索发现 -> 阅读理解 -> 有依据的总结分析”；筛选、文库和同步服务于这条主线。 |
| F3 | AI 输出的可信度契约 | 回答和总结必须给出论文依据、可跳转位置与局限；没有证据时明确说明，不生成伪引用。 |
| F4 | 模型与成本策略 | 保留一个强模型和一个低成本模型，供应商可配置；自动测试不用付费 API，真实调用有预算上限。 |
| F5 | PDF service 的交付方式 | 最终由桌面应用托管和自动启停，用户不手动运行 Python；启动失败时提供诊断和重试。 |
| F6 | 检索结果的产品取向 | 首屏优先高相关性的约 20 篇结果，展示来源和匹配理由，再允许扩大召回范围。 |
| F7 | 百度同步的定位 | 保留为用户主动开启的备份能力，不阻塞检索和阅读主流程，不默认上传论文内容。 |
| F8 | 隐私与遥测 | 默认无内容遥测；只有在单独对齐隐私说明后，才考虑用户可关闭的匿名崩溃信息。 |

### 界面设计

| 编号 | 需要确认的问题 | 建议默认值 |
| --- | --- | --- |
| U1 | 一级信息架构 | 保持“发现 / 阅读 / 分析”，历史、同步和设置作为工具入口，不增加营销首页。 |
| U2 | 阅读工作区 | 桌面端采用目录、PDF、AI/笔记三栏；左右栏可收起，正文始终是视觉中心。 |
| U3 | 窄窗口交互 | 小于约 1100px 时折叠目录与文库，PDF 和 AI 使用分段切换，避免横向挤压。 |
| U4 | AI 结果呈现 | 先给结论和依据，再展开推理细节、局限和相关章节；证据点击后定位到原文。 |
| U5 | 视觉风格与密度 | 使用克制、紧凑、适合长时间工作的研究工具界面；弱化装饰卡片和大标题。 |
| U6 | 文库入口 | 保留阅读页中的轻量论文抽屉，同时提供完整文库管理视图处理批量操作。 |
| U7 | 语言策略 | 界面以中文为主，论文标题、术语和原文保留原语言，翻译是可切换的辅助层。 |
| U8 | 操作反馈 | 长任务持续显示阶段、进度、取消和可恢复状态；成功反馈安静，失败反馈可行动。 |

### 自治权限

建议授予：

- 允许自动创建和切换 `codex/*` 分支。
- 允许在通过对应测试和 secret scan 后自动 commit。
- 允许自动 push `codex/*` 分支并创建 PR。
- 允许在本机启动服务、桌面应用和测试进程。
- 允许使用本地测试凭证执行有限次数的真实 E2E。

建议继续人工批准：

- 合并 PR。
- 正式发布。
- Git 历史重写与强制推送。
- 任何新增付费服务或提高预算。
- 真实云数据的删除、覆盖与灾难恢复演练。

## 四、凭证与本地文件交接规则

### 绝对不要做

- 不要把 API key、token、密码或证书粘贴到聊天、Markdown、Issue 或 PR。
- 不要把真实密钥写入 `.example` 文件。
- 不要把凭证放进前端代码、浏览器存储、截图或测试 fixture。
- 不要因为“只是私有仓库”而提交秘密。

### 正确交接方式

1. 从已有模板创建本地文件：

```bash
cp config/semantic_scholar.json.example config/semantic_scholar.json
cp config/strong_llm.json.example config/strong_llm.json
cp config/weak_llm.json.example config/weak_llm.json
cp baiduyun_token.json.example baiduyun_token.json
```

2. 你在本机编辑真实值。这四个目标文件已经被 `.gitignore` 排除。
3. 只回复“哪个文件已配置”，我会通过脱敏检查和最小请求验证，不显示秘密。
4. 每次 commit 或 push 前运行：

```bash
bash scripts/secret_scan.sh
git status --short --ignored
```

当前 Git 历史仍有历史秘密风险。公开仓库或正式发布前，必须先按 `docs/superpowers/plans/2026-06-11-secret-history-remediation.md` 轮换受影响凭证并执行经确认的历史重写。

## 七、完成标准

长期自治开发的前置条件满足，意味着：

- 产品核心、短期界面方向和隐私边界已经明确。
- Agent 对分支、commit、push、PR、真实 E2E 的权限清楚。
- 必要凭证存在于本地忽略文件中，不需要通过聊天传递。
- 日常测试不依赖付费或个人账号，真实 E2E 有预算和数据边界。
- 高风险操作保留明确人工闸门。
- 每轮工作都能留下代码、测试证据、文档、提交和下一步，而不是只有对话结论。
